1. Justificación de Spring Boot

En el desarrollo de software enfocado en la arquitectura de microservicios y backend empresarial, la agilidad, robustez y facilidad de mantenimiento son fundamentales. Aquí es donde Spring Boot se justifica como la herramienta líder para el ecosistema Java.

¿Qué es Spring Boot y para qué sirve?

Spring Boot es un framework open-source basado en Java, desarrollado sobre el ecosistema del Spring Framework original. Su objetivo principal es simplificar el proceso de configuración y despliegue de aplicaciones Java empresariales.

Sirve para crear aplicaciones autónomas (stand-alone) que se ejecutan directamente con un servidor web embebido (como Tomcat, Jetty o Undertow), sin necesidad de instalar o desplegar externamente servidores de aplicaciones pesados (como WebLogic, Wildfly o Glassfish).

Concepto Clave: Convención sobre Configuración

Spring Boot promueve la filosofía de "Convention over Configuration". Esto significa que viene preconfigurado con las decisiones tecnológicas más comunes y recomendadas, permitiendo al desarrollador escribir código inmediatamente en lugar de pasar horas configurando archivos XML o Java.

¿Qué aplicaciones y casos de uso tiene?

  • APIs RESTful y Microservicios: Es el estándar para la creación de servicios web ligeros, escalables e interconectados bajo arquitecturas distribuidas (Cloud Native).
  • Aplicaciones Web Monolíticas: Permite renderizar vistas HTML dinámicas en el lado del servidor integrándose con motores de plantillas como Thymeleaf, FreeMarker o JSP.
  • Procesamiento en Lote (Spring Batch): Ideal para tareas programadas automatizadas de alta concurrencia que procesan grandes volúmenes de registros (ETL).
  • Integración y Streaming: Facilita la comunicación orientada a mensajes mediante integraciones con Apache Kafka, RabbitMQ y JMS.

¿Sobre qué lenguajes se apoya?

Aunque el núcleo del ecosistema está escrito en Java, Spring Boot proporciona soporte nativo de primera clase para:

  • Java: Versión 17 y 21 son actualmente las más utilizadas y recomendadas por su soporte a largo plazo (LTS).
  • Kotlin: El lenguaje moderno de JetBrains, con una sintaxis limpia y interoperabilidad del 100% con las librerías Java.
  • Groovy: Lenguaje de scripting dinámico compatible con la Máquina Virtual de Java (JVM).

Prerrequisitos Técnicos

Antes de comenzar en Spring Boot, hay que cumplir con los siguientes requisitos:

  1. Conocimientos sólidos de programación orientada a objetos (POO) en Java.
  2. Familiaridad con la arquitectura MVC y el protocolo HTTP.
  3. Tener instalado el Java Development Kit (JDK) 17 o superior en tu máquina.
  4. Familiaridad básica con herramientas de automatización de construcción (Build Tools) como Maven o Gradle.

2. Instalación y Configuración del Entorno

Para empezar a codificar con Spring Boot, no necesitamos instalar un "programa" o framework global en el sistema operativo. En su lugar, el framework se añade como dependencias del proyecto de software mediante un gestor de construcción. Sin embargo, debemos preparar nuestro entorno de desarrollo.

Paso 1: Instalación de Java JDK y Variables de Entorno

Spring Boot 3.x requiere como mínimo Java 17. Para verificar si lo tienes instalado, abre tu consola o terminal (PowerShell en Windows, Terminal en macOS/Linux) y escribe:

Consola 
java -version

Si la consola no reconoce el comando, se debe descargar e instalar un JDK (por ejemplo, Temurin de Adoptium u Oracle JDK). Además, se debe configurar las siguientes variables de entorno en el sistema:

  • JAVA_HOME: Debe apuntar a la ruta raíz donde se instaló el JDK (ej. C:\Program Files\Eclipse Adoptium\jdk-21.0.10.8-hotspot).
  • Path: Debe incluir la ruta a la carpeta binaria del JDK (ej. %JAVA_HOME%\bin).

Paso 2: Herramientas de Construcción (Maven o Gradle)

Las aplicaciones Spring Boot gestionan sus librerías a través de herramientas de construcción. Las rutas y dependencias se especifican en:

  • pom.xml (si usas Maven): Archivo XML estándar que define el modelo del proyecto y sus dependencias.
  • build.gradle (si usas Gradle): Script en lenguaje Groovy o Kotlin más compacto y flexible para la automatización.

Paso 3: Inicializar un Proyecto base con Spring Initializr

La forma más recomendada para crear un proyecto base es usar la web oficial Spring Initializr:

  1. Selecciona el gestor de dependencias (por ejemplo, Maven Project).
  2. Selecciona el lenguaje (Java).
  3. Elige la versión de Spring Boot (selecciona una versión estable que no diga "SNAPSHOT" ni "M").
  4. Ingresa los metadatos de tu proyecto (Group, Artifact, Name, Package name).
  5. Elige el empaquetado (Jar es el estándar recomendado para servidores embebidos).
  6. Selecciona la versión de Java instalada (ej. 17 o 21).
  7. Agrega dependencias iniciales. Para una API REST base añade: Spring Web.
  8. Haz clic en Generate para descargar un archivo comprimido .zip. Descomprímelo en tu carpeta de trabajo.
¿Necesitaremos una Base de Datos?

Para empezar a aprender y desarrollar nuestros primeros endpoints NO necesitamos instalar una base de datos externa (como PostgreSQL o MySQL). Podemos utilizar H2 Database, una base de datos relacional ultraligera en memoria que se configura automáticamente y se destruye al apagar la aplicación, facilitando pruebas inmediatas.

3. Primeros Pasos: "Hola Mundo"

Una vez descargado y abierto el proyecto en un Entorno de Desarrollo Integrado (IDE) como IntelliJ IDEA, Eclipse o VS Code, veremos la estructura típica de directorios. Vamos a escribir nuestro primer controlador HTTP interactivo.

Estructura del Proyecto Generado

  • src/main/java: Aquí reside todo el código fuente Java organizado en paquetes.
  • src/main/resources: Archivos de configuración como application.properties y recursos estáticos.
  • pom.xml: El archivo de dependencias de Maven.

Creación del Punto de Entrada de la Aplicación

Toda aplicación Spring Boot tiene una clase principal con el método `main` decorado con la anotación clave `@SpringBootApplication`:

Java (DemoApplication.java) 
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {
    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}

Creación del Controlador REST

Para que nuestra aplicación responda a solicitudes HTTP desde el navegador, creamos una nueva clase Java en el mismo paquete de nuestra aplicación llamada `HelloController`:

Java (HelloController.java) 
package com.example.demo;

import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.bind.annotation.GetMapping;

@RestController
public class HelloController {

    @GetMapping("/hola")
    public String decirHola() {
        return "¡Hola Mundo desde Spring Boot!";
    }
}

Explicación de las Anotaciones

  • @RestController: Le dice a Spring que esta clase es un controlador web encargado de recibir solicitudes y responder directamente con texto, JSON o XML.
  • @GetMapping("/hola"): Indica a Spring que cuando un cliente realice una solicitud HTTP de tipo `GET` a la ruta `/hola`, debe ejecutar el método asociado `decirHola()` y devolver el valor del `return`.
¿Cómo probarlo?

Se puede ejecutar el método main directamente desde el IDE, o ejecutar en la consola: mvnw spring-boot:run. El servidor Tomcat embebido se iniciará en el puerto predeterminado 8080. Abre tu navegador y accede a http://localhost:8080/hola para ver el resultado.

4. Utilización del Framework: API REST CRUD

Para entender la verdadera potencia de Spring Boot, debemos explorar cómo construir una estructura clásica de tres capas (Controlador, Servicio y Repositorio) con operaciones CRUD (Create, Read, Update, Delete) conectada a base de datos.

El Modelo / Entidad (Dominio)

Supongamos que creamos un sistema de gestión de tareas. Creamos una clase `Tarea` utilizando anotaciones de JPA (Java Persistence API) para mapearla a una tabla de base de datos relacional:

Java (Tarea.java) 
package com.example.demo.model;

import jakarta.persistence.Entity;
import jakarta.persistence.Id;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;

@Entity
public class Tarea {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String titulo;
    private boolean completada;

}

Acceso a Datos (Capa de Repositorio)

Gracias a Spring Data JPA, la persistencia y consultas básicas a base de datos se logran creando simplemente una interfaz que hereda de `JpaRepository` sin escribir una sola línea de implementación SQL:

Java (TareaRepository.java) 
package com.example.demo.repository;

import com.example.demo.model.Tarea;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Repository;

@Repository
public interface TareaRepository extends JpaRepository<Tarea, Long> {
    // Hereda métodos como findAll(), findById(), save(), deleteById()
}

Lógica de Negocio (Capa de Servicio)

Es una buena práctica separar la lógica de presentación de la lógica de negocio mediante clases decoradas con @Service:

Java (TareaService.java) 
package com.example.demo.service;

import com.example.demo.model.Tarea;
import com.example.demo.repository.TareaRepository;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class TareaService {
    
    @Autowired
    private TareaRepository repository;

    public List<Tarea> obtenerTodas() {
        return repository.findAll();
    }

    public Tarea guardar(Tarea tarea) {
        return repository.save(tarea);
    }
}

Controlador REST Completo (CRUD)

Finalmente, exponemos los servicios web. El framework maneja automáticamente la serialización y deserialización de datos Java a formato JSON (usando internamente la librería Jackson):

Java (TareaController.java) 
package com.example.demo.controller;

import com.example.demo.model.Tarea;
import com.example.demo.service.TareaService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/api/tareas")
public class TareaController {

    @Autowired
    private TareaService service;

    @GetMapping
    public List<Tarea> listar() {
        return service.obtenerTodas();
    }

    @PostMapping
    public Tarea crear(@RequestBody Tarea nuevaTarea) {
        return service.guardar(nuevaTarea);
    }
}
Visualización de Resultados

Para comprobar que la API funciona, no basta con usar el navegador (ya que este solo realiza peticiones GET por defecto). Se recomienda utilizar herramientas cliente de APIs REST como Postman, Insomnia o el cliente HTTP integrado del IDE, enviando peticiones POST con cuerpos de mensaje JSON para guardar registros y probando los diferentes verbos HTTP.

5. Explicación del Funcionamiento del Framework

Para dominar Spring Boot, es indispensable entender como funciona a fondo. El framework se basa en conceptos arquitectónicos muy potentes.

Inyección de Dependencias e Inversión de Control (IoC)

Spring funciona mediante un Contenedor IoC (Inversion of Control). En lugar de crear manualmente instancias de clases usando la palabra reservada `new` (por ejemplo, `TareaService service = new TareaService()`), se delega esta responsabilidad a Spring.

Spring escanea la aplicación al arrancar, identifica las clases con anotaciones estereotipo (`@Component`, `@Service`, `@Repository`, `@RestController`), las instancia y las administra como objetos reutilizables llamados Beans en el contexto de la aplicación.

Cuando una clase necesita interactuar con otra (como el controlador que requiere el servicio), usamos la anotación `@Autowired` (o inyección por constructor). Spring busca el bean requerido en su contenedor y lo "inyecta" (conecta) de forma automática.

1
Escaneo de Clases

Spring escanea los paquetes buscando anotaciones del framework para instanciar los componentes.

2
Contenedor IoC

Los componentes creados (Beans) se guardan y gestionan en un almacén de memoria centralizado.

¿Cómo actúa sobre archivos o páginas?

Spring Boot no modifica directamente archivos de tu disco duro al ejecutarse, sino que opera en la memoria de la JVM. Actúa como una capa intermedia entre el servidor web embebido y el código Java:

  1. Una petición HTTP llega al puerto `8080`.
  2. El servidor embebido (Tomcat) la recibe y la redirige al servlet central de Spring: el `DispatcherServlet`.
  3. Este servlet analiza la ruta de la petición y localiza qué método controlador (`@RestController`) mapea a esa ruta.
  4. Ejecuta el código Java, obtiene el objeto devuelto y utiliza serializadores para retornar la respuesta (HTML, JSON o texto plano) al cliente.

Referenciar ficheros desde otras aplicaciones (CORS)

En el desarrollo de software actual, el frontend (HTML/JS en React, Angular o Vue) se aloja en un servidor diferente (ej. puerto `3000`) al backend de Spring Boot (puerto `8080`).

Por motivos de seguridad, los navegadores bloquean las solicitudes entre distintos dominios a menos que configures CORS (Cross-Origin Resource Sharing). En Spring Boot, puedes habilitarlo fácilmente a nivel de controlador usando la anotación @CrossOrigin:

Java (CORS ejemplo) 
@CrossOrigin(origins = "http://localhost:3000")
@RestController
public class HelloController {
    // Los métodos de este controlador ahora admiten peticiones de React/Vue
}

6. Conclusiones y Alcance del Tutorial

Se ha recorrido los fundamentos esenciales que estructuran y dan forma al framework Java más demandado en la actualidad.

Objetivos Conseguidos

Al finalizar este tutorial, se habrá aprendido:

  • El propósito y la justificación del framework en el desarrollo empresarial moderno.
  • A configurar las herramientas e inicializar un proyecto base limpio de Spring Boot.
  • A codificar controladores y mapear endpoints a rutas HTTP (GET/POST).
  • La arquitectura interna en capas del framework y cómo se comunican a través de la inyección de dependencias.
  • A configurar la conectividad con bases de datos en memoria para propósitos de prueba de forma transparente.

Alcance del Framework

Spring Boot no se limita al desarrollo de APIs REST simples. Su alcance cubre sistemas empresariales de alta disponibilidad:

  • Seguridad Avanzada (Spring Security): Permite implementar autenticación por JWT, OAuth2 y control de acceso robusto por roles a nivel de endpoint.
  • Monitoreo en Producción (Spring Boot Actuator): Expone métricas críticas (uso de CPU, hilos activos, salud de la base de datos) que pueden ser recolectadas por herramientas como Prometheus y Grafana.
  • Despliegue y Contenedores: La capacidad de empaquetar aplicaciones en un archivo JAR autocontenido facilita enormemente su dockerización y despliegue automatizado en entornos Kubernetes o plataformas Cloud (AWS, Azure, GCP).

Ejercicios Prácticos y Retos de Aprendizaje

Para reforzar los conocimientos teóricos adquiridos, se proponen la realización de tres ejercicios prácticos. Puedes intentar codificar las soluciones en tu entorno local.

1 Reto 1: Endpoints con Variables de Ruta

Descripción: Crea un endpoint en tu controlador que reciba una variable de ruta dinámica usando la anotación @PathVariable. El endpoint debe mapearse a /saludar/{nombre} y responder con un mensaje personalizado que incluya el nombre de la variable de la ruta.

Concepto a practicar: @PathVariable, mapeo dinámico de URLs.

2 Reto 2: Configuración de Puerto

Descripción: Por defecto, Spring Boot arranca en el puerto 8080. Modifica el archivo de configuración application.properties para cambiar el puerto de escucha del servidor al puerto 9090 y agrega una propiedad personalizada para cambiar el nombre de la app.

Concepto a practicar: Propiedades del servidor (server.port), archivos properties.

3 Proyecto Integrador: API de Biblioteca Simple

Enunciado: Crea un esqueleto de aplicación Spring Boot utilizando Spring Initializr con dependencias Spring Web y H2 Database. Diseña una clase modelo Libro (con atributos id, titulo, autor y anioPublicacion). Implementa una interfaz de repositorio que extienda de JpaRepository y un RestController que implemente dos operaciones básicas:

  • GET /api/libros: Para listar todos los libros guardados en la base de datos.
  • POST /api/libros: Para crear e insertar un nuevo libro (enviado como cuerpo JSON).
